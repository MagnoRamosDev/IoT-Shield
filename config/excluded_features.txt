# ==============================================================================
# 🛡️ IOT-SHIELD: LISTA DE FEATURES EXCLUÍDAS DO TREINAMENTO (ANTI-BIAS)
# ==============================================================================
# Este arquivo dita quais features o Random Forest deve ignorar.
# O objetivo principal desta organização é focar no "comportamento" dos Botnets 
# (taxa de varredura, persistência) e não em metadados estáticos ou ruídos da rede.
# ==============================================================================

# ------------------------------------------------------------------------------
# 1. IDENTIFICADORES ESTÁTICOS DE TOPOLOGIA
# Motivo: Evitar Overfitting. Se não excluirmos, a IA vai decorar que "Telnet (23) é
# malicioso" e ignorará malwares que usem portas HTTP ou protocolos UDP mascarados.
# ------------------------------------------------------------------------------
src_port
dst_port
protocol

# ------------------------------------------------------------------------------
# 2. MÉTRICAS DE VOLUME ABSOLUTO (DURAÇÃO INDEFINIDA)
# Motivo: Ataques como Mirai podem durar 2 segundos ou 2 dias. Focar em valores
# brutos de bytes e pacotes cria um viés no tamanho do pcap coletado. A IA deve 
# olhar para taxas proporcionais e comportamentos relativos, não a contagem bruta.
# ------------------------------------------------------------------------------
src2dst_bytes
dst2src_bytes
src2dst_packets
dst2src_packets
bidirectional_packets

# ------------------------------------------------------------------------------
# 3. ASSINATURAS ESTRITAS DE TAMANHO DE PACOTE (PAYLOAD OVERFITTING)
# Motivo: Para forçar a IA a não "decorar" o tamanho do byte do exploit do Bashlite.
# Malwares podem alterar o "padding" para enganar a IA. Focamos apenas se o tamanho
# é *constante* (feature de engenharia boolean) e não nos seus valores literais em bytes.
# ------------------------------------------------------------------------------
bidirectional_min_ps
src2dst_min_ps
dst2src_min_ps
bidirectional_max_ps
src2dst_max_ps
dst2src_max_ps
src2dst_mean_ps
bidirectional_mean_ps
dst2src_mean_ps
dst2src_stddev_ps
src2dst_stddev_ps
bidirectional_stddev_ps

# ------------------------------------------------------------------------------
# 4. RUÍDO DE LATÊNCIA DA REDE (PIAT - Packet Inter-Arrival Time)
# Motivo: Min_PIAT geralmente reflete o limite físico do cabo. StdDev/Mean_PIAT 
# sofrem fortes variações devido a jitter de Wi-Fi e atrasos na rede local (NAT), 
# gerando falso-positivos em redes ruins. Focamos apenas nos "Picos" (Max PIAT).
# ------------------------------------------------------------------------------
src2dst_stddev_piat_ms
src2dst_mean_piat_ms
src2dst_min_piat_ms
dst2src_stddev_piat_ms
bidirectional_min_piat_ms
bidirectional_stddev_piat_ms
dst2src_min_piat_ms

# ------------------------------------------------------------------------------
# 5. COMPORTAMENTO DA VÍTIMA E PACOTES DE ENCERRAMENTO (RST)
# Motivo: Um port-scan pode receber pacotes RST de portas fechadas ou apenas
# Silêncio/Timeout. Analisar o lado do "alvo" polui o dado porque depende do S.O.
# da vítima (Linux vs Windows). Focamos majoritariamente nos SYNs gerados pelo atacante.
# ------------------------------------------------------------------------------
dst2src_syn_packets
dst2src_rst_packets
src2dst_rst_packets
bidirectional_rst_packets

# ------------------------------------------------------------------------------
# 6. REDUNDÂNCIAS GERAIS
# Motivo: Já usamos métricas direcionais concisas; combinar as duas causa
# multicolinearidade desnecessária para as árvores de decisão.
# ------------------------------------------------------------------------------
bidirectional_concurrent_flows
